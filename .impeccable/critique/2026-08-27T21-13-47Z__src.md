## Overall Impression

The plumbing is excellent and the design is generic. URL-shareable state, honest per-card pricing math, and complete state coverage are better than most production dashboards. But the surface has no point of view: 368 models in one undifferentiated stream, a 68-option native select for the most-used filter, and the one risk signal that matters visually diluted to chip-noise by amber overload. Biggest opportunity: make recency the composition, not the default sort.

## What's Working

1. Shareable-state engine — every filter, sort, and assumption round-trips through URL params; SearchFilter auto-expands when a range param is present (?priceMax=5 deep-links already-explained).
2. Honest, visible pricing math — each card states "per 1M tokens · 10% output, 77.8% cache hit" under its stat pills (ModelCard.tsx:565-567).
3. Complete state trio — geometry-matching SkeletonGrid, distinct ErrorState with retry, EmptyState echoing active filter chips with one-click clear.

## Priority Issues

[P1] Search relevance loses to recency sort — typing 'claude' surfaces ByteDance Seed-2.0-Code above actual Claude models (description-substring matches inherit newest-first ordering). Core loop is search→pick→copy ID; one misleading first result destroys trust. Fix: relevance sort when query non-empty (name exact > prefix > ID > description, recency tiebreak); show "Sorted by relevance" while searching.

[P1] Provider filter is a native select with 68 options — most-used filter forces open-and-scroll hunting, no multi-select, mobile OS sheet hides result count. Fix: searchable combobox (type-ahead + multi-select checkboxes + selected-provider chips).

[P1] AVG semantics invisible; 'Varies'-priced models silently excluded by price filters — formula lives in collapsed panel, caveats repeated as 40 invisible footnotes; NaN comparisons make unpriced models vanish without explanation when a price bound activates. Violates Product Principle 2. Fix: exclude from only the unsatisfiable bound, announce ("12 models without published prices hidden") + chip entry; teach the formula once per page.

[P2] Reset silently deletes saved cost assumptions — header Reset reads as "clear filters" but wipes localStorage-persisted assumptions. Destructive × irreversible × invisible. Fix: reset filters only; separate assumptions reset inside the panel; or undo toast.

[P2] Amber overload + badge noise dilute the warning that matters — amber carries 3 meanings (benchmark, training warning, audio modality); up to six 10px badges per card; (free)/($$$$) suffix noise. Fix: reserve amber for risk, own hue for benchmark, neutral modality colors, suffixes into badges. Also: violet gradient logo at ModelsBrowser.tsx:643 (ai-color-palette detector finding).

## Persona Red Flags

Riley (Stress Tester): avgOutputShare=999 silently clamped — shared links show different numbers than sender saw. Free-only + price range contradictory but allowed → plausible-looking zero. Reset deletes persistent settings.

Sam (Accessibility): role="status" on TrainingWarning announces ~6x per page load (static content, not live region). 10px type in badges/footnotes below comfortable minimum. TerminalBench tooltip content unreliably announced. Positive: focus-visible rings consistent, date inputs have aria-labels, reduced-motion respected.

## Minor Observations

- Grid card header justify-between with single child — dead right slot; NEW/FREE could anchor there.
- EmptyState chip key={chip} collides on duplicate chip text.
- Skeleton cards shorter than real cards (no badge row) → reflow jump.

## Questions to Consider

- If recency is the lens, why is "what's new" a sort order rather than the front page — a dated digest above an archival browser?
- Could a card survive with only three numbers — one price, one capability, one risk?
- Is provider a filter at all, or the second axis of the surface (grouped sections, sticky provider rail)?
